## 4. 결함이 계속 나오는 이유

세 가지 패턴이 반복됩니다.

1. **키워드 규칙과 열린 한국어 입력의 간극.** 반말 저정보 답(E3), 띄어쓰기
   변형(D3), 동의 표현 변형(D2), 메타 발화 변형(P1)이 모두 같은 종류입니다.
   규칙을 하나씩 고치면 그 표현은 해결되지만, 다음 변형에서 또 나옵니다.
2. **원격 GPT가 의도보다 넓게 개입함.** 복구 턴(P3)과 확인 질문(P4)은 결정론
   문장이 정해져 있는데, 라우터가 상태만 보고 GPT를 허용해 문장이 바뀌었습니다.
   GPT가 한 턴에 질문 두 개를 묻는 문제도 있습니다(N6 백로그).
3. **평가 사용자가 너무 협조적임.** 13.6 평가의 시뮬레이션 사용자는 질문에
   맞게 답합니다. 실제 사용자는 헷갈려하고, 짧게 답하고, 화를 냅니다. 게이트가
   0이어도 기기에서 결함이 나오는 이유입니다.

그래서 다음 계획은 결함 네 건 수정(13.8)과 함께, 2·3번 패턴을 구조적으로
막는 것(13.8의 P3, 13.9)을 포함합니다.

#### (계획 원문) 13.8 P1~P4 수정

각 결함은 기존 방식대로 진행합니다. 기기 대화를 재현한 테스트를 먼저 만들고,
수정 전 코드에서 실패하는 것을 확인한 뒤 고칩니다. 진행 순서는 작은 것부터이며,
앞 수정이 뒤 결함을 관찰하는 데 영향을 줍니다.

1. **P3: 복구 턴은 항상 결정론.** 라우터가 메타 발화 대응, 목표 소진 대응 계획에는
   GPT를 허용하지 않게 합니다. 가장 작은 수정이고, 이후 기기에서 보이는 복구
   문장이 테스트와 같아집니다.
2. **P2: 라운드 걱정은 생각 형태인 발화만.** 첫 목표 질문 이전의 사용자 발화 중
   생각 형태인 가장 최근 것을 고릅니다. 메타 발화로 복구된 턴은 이미 제외돼 있습니다.
3. **P1: '헷갈림' 복구 유형 추가.**
   - 검출 대상: 챗봇의 말을 이해하지 못했다는 표현("무슨 말이야", "뭐라는
     거야", "무슨 말 하는지 모르겠어", "무슨 이야기를 하는 거야").
   - 걱정 자체에 대한 "모르겠어"(저정보 답)와는 구분합니다. 판단 근거는 "무슨
     말", "뭐라는" 같은 대상 표현과 2인칭("너가")입니다.
   - 응답은 결정론 문장입니다. 예: "제 말이 헷갈리게 들렸나 봐요. 쉽게 다시 여쭤볼게요."
     뒤에 대기 중이던 질문을 쉬운 말로 다시 묻습니다.
   - 이런 턴은 기법 대상, 기법 답, 요약 대상으로 쓰지 않습니다. 기존 메타 발화와
     같은 처리입니다.
4. **P4: 저정보 답이 이어지면 더 묻지 않음.** reflect 확인 질문에 저정보 답이
   두 번 이어지면 부담 없이 받아 준 뒤 마무리를 제안합니다. 예: "지금은
   떠오르지 않을 수 있어요. 오늘은 여기까지 정리해 볼까요, 아니면 조금 더
   이야기하고 싶으신가요?"

   다시 열린 라운드에서도 같은 규칙을 적용하므로 계속하기는 여전히 1회까지입니다.

결정이 필요한 것은 P1의 응답 문장 톤, P4의 "두 번"이라는 기준입니다. 위
예시로 진행하고, 13.10 dogfood에서 확인한 뒤 조정합니다.

### 13.9 비협조적 사용자 평가 추가

13.6 평가에 실제 기기에서 나온 사용자 유형을 넣습니다. 목표는 게이트가
0이면 기기에서도 같은 종류의 결함이 나오지 않게 하는 것입니다.

평가 세트는 둘로 나눕니다. 검출기를 만들 때 쓴 표현으로 다시 평가하면
게이트가 0이어도 기기에서 무너질 수 있기 때문입니다(Phase 11/12 경험).

- **13.9A 기존 결함 회귀:** dogfood에서 나온 D/E/P 사례입니다. 구현에 사용하고, 반드시 0이어야 합니다.
- **13.9B 동결 holdout:** 13.9A 구현이 끝난 뒤 작성해 동결합니다. 의미는 같지만 표면이
  다른 표현으로 구성하며, 수정에는 쓰지 않습니다. holdout이 실패하면 원인을
  기록하고, 수정은 새 개발 세트로 합니다. holdout 문장은 바꾸지 않습니다.

holdout에 넣을 변형:
- 존댓말 / 반말
- 띄어쓰기 있음 / 없음
- 한 단어 / 긴 문장
- 메타 발화와 걱정 내용의 혼합(예: "뭔 소린지 모르겠어 그냥 발표 때문에 걱정된다는 건데")
- 화난 표현
- 간접 표현
- 두 문장 이상

추가할 사용자 유형:
- 헷갈려하는 사용자: 단계마다 "무슨 말이야" 류를 섞음
- 계속 짧게만 답하는 사용자: "몰라", "응", "잘 모르겠어"를 반말과 존댓말로
- 메타 발화 사용자: reflect, 기법 질문 직후, 마무리 제안 직후에 반복 지적
- 화내는 사용자: "짜증나게", "왜 계속 같은 말해"
- 표기 변형: 띄어쓰기 없음, 반말, 문장 여러 개

추가할 게이트 지표 (모두 0이어야 함):

| 지표 | 뜻 |
|---|---|
| nonAnswerCredited | 메타 발화나 저정보 답을 기법 답으로 인정함 (P1) |
| metaAsTarget | 메타 발화를 인용하거나 기법 대상으로 씀 (P1, P2) |
| remoteOnRepair | 복구 턴이 GPT로 실현됨 (P3) |
| repeatedClarifyRun | 확인 질문이 저정보 답 뒤에 세 번 이상 이어짐 (P4) |
| deadTurnStatement | 마무리 확정 전에 질문 없는 문장만 내보내고 사용자 답을 기다림 (E3) |

원격 GPT 표현은 테스트에서 재현하기 어렵습니다. 그래서 remoteOnRepair는
라우팅 결정을 검사하고, 문장 품질 자체는 13.10 기기 확인으로 봅니다.

### 13.10 실기기 dogfood 2차

새 빌드로 4주차 계정 2세션, 5~6주차 계정 1세션을 진행합니다. 5~6주차 세션은
DB에서 계정 주차를 바꿔 행동 계열 기법을 확인하기 위한 것입니다.

세 세션은 "정상 사용자"처럼 하지 말고, 역할을 나눠 의도적으로 깨뜨립니다.

- **세션 A, 헷갈려하는 사용자:** "무슨 말인지 모르겠어", "그게 무슨 뜻이야", "뭐라는 거야", "잘 모르겠는데"
- **세션 B, 비협조적이고 짜증 난 사용자:** "몰라", "응", "모르겠다고", "왜 계속 물어봐", "짜증나"
- **세션 C, 섞인 사용자:** 정상적으로 답하다가 중간에 메타 발화와 걱정 내용을 섞습니다. 예: "근데 아까도
  이거 물어본 것 같은데", "잘 모르겠어 그냥 발표 망칠까봐 걱정돼"

확인 목록:
- 세션 4를 그대로 다시 해 보기: 헷갈림 발화, 저정보 답 반복, 반복 지적
- 기법 질문 직후 메타 발화. 지금까지 기기에서 한 번도 확인되지 않았습니다.
- 행동 계열 기법 질문("그 걱정이 들 때 보통 어떻게 하시나요?")이 자연스러운지
- 로그아웃 재발 여부. 이번에 토큰 만료로 추정했으나 확인하지 않았습니다.

표현 수준의 어색함은 태그를 막지 않고 N6 백로그로 넘깁니다.

## 6. 결함을 다루는 방식 (고정)

새 dogfood 결함이 나올 때마다 정규식을 하나 추가하는 방식은 끝이 없습니다.
앞으로는 다음 순서를 고정합니다.

1. 결함 발견
2. 의미 범주 정의
3. 메타데이터와 계약 정의
4. 결정론 정책 구현
5. 기기 대화 재현 테스트
6. 적대적 holdout
7. 기기 확인

## 7. 태그 이후

태그 뒤에는 기능을 더 붙이지 않고, 제품 baseline을 한 번 동결합니다. 그 뒤로는
두 트랙으로 나눕니다.

- **트랙 A, 제품 품질 (Phase 14: 표현·실현 품질):** N6, 한 턴에 질문 여러 개,
  부자연스러운 원문 인용, 유도 질문, 원격 GPT 범위와 프롬프트 재평가. 바로
  `realize_v3`를 만들지 않습니다. 먼저 N6 사례를 모아 단계별로 나눠 봅니다:
  선택이 맞았는지, 결정론 계획이 맞았는지, 원격 출력이 틀렸는지, 검증기가
  무엇을 놓쳤는지. 그다음 프롬프트 문제인지 검증기 문제인지 가립니다.
- **트랙 B, 임상·콘텐츠:** 1~3주차 기법과 microSupport 임상 승인,
  `week3_alternative_thought_01` 승인 여부, 누적 기법 목록 확장.

## 8. 태그 이후 백로그

- **N6 표현 단계:** GPT가 한 턴에 질문 두 개를 하는 문제, 긍정 쪽으로 유도하는
  질문("어떤 긍정적인 영향이…"). 원격 GPT 실현 방식은 동결을 풀어야 해서 별도
  단계로 진행합니다.
- **F4 잔여:** 저정보 답 인용이 남은 경로가 있는지 13.9 평가로 확인합니다.
- **1~3주차 기법 승인:** 임상 검수 후 추가합니다(사용자 결정 사항).
- **"~할 수 있을까" 형태:** "내일 시험은 잘 볼 수 있을까" 같은 의문형 걱정을
  생각 형태로 볼지 결정해야 합니다. 지금은 확인 질문으로 처리합니다.
