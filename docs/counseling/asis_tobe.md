# 상담 챗봇 AS-IS / TO-BE

기준: 2026-10-04. 예전 챗봇 두 단계(AS-IS)와 지금 챗봇(TO-BE)을 비교합니다. 지금 구조의 상세는
[`chatbot_system.md`](chatbot_system.md), 실행과 인수인계는 [`../chatbot_HANDOVER.md`](../chatbot_HANDOVER.md)에 있습니다.

| 구분 | 시기 | 한 줄 요약 |
|---|---|---|
| **AS-IS 1** 초기 GPT 챗봇 | ~2026-03 | GPT가 긴 프롬프트로 매 턴 자유롭게 답함. 근거·안전·검증 장치 없음 |
| **AS-IS 2** 결정론 상담 엔진 | ~2026-10-02 | 코드가 대화의 모든 결정을 하고 GPT는 일부 문장만 다듬음. 안전하지만 경직됨 |
| **TO-BE** 경계 안의 LLM 주도 + 결정론 대체 | 2026-10-03~ | GPT가 코드가 정한 경계 안에서 대화를 이끌고, 코드가 검증. 실패한 턴만 결정론 경로가 답함 |

---

## 1. 구조

**AS-IS 1: 초기 GPT 챗봇**

```
사용자 발화 → Orchestrator
  → 주차별 컨셉 문구 + 더미 사용자 데이터 요약 + RAG 유사 사례(유사도 0.6 이상)
  → GPT 자유 생성 (매 턴)
  → (별도 호출) 인지왜곡 판정 GPT — 기록만, 응답에 반영 안 함
  → (별도 호출) 표정 판정 GPT → 상담사 그림 9종 중 하나
```

**AS-IS 2: 결정론 상담 엔진**

```
사용자 발화 → SafetyGate → 코퍼스 검색 → 정책 파이프라인(Hard Guard → 상태별 selector → 검증 → 문장 계획)
  → 일반 탐색·되짚기 턴만 GPT가 문장 다듬기(검증 실패 시 코드 문장) → 상태 전이
```

**TO-BE**

```
사용자 발화 → SafetyGate(위기면 고정 응답)
  → B: 코드가 경계 구성(사용자 기록·앱 사실·승인 기법·용어 정의·회상 대상, 모두 id 목록)
       → GPT 1회, 요청마다 id를 enum으로 고정한 JSON 스키마 → 검증기
       ├ 통과 → B 응답
       └ 거절·오류·시간 초과 → A(= AS-IS 2 엔진)가 이번 턴만 답함
  → 같은 턴 메타데이터 → 상태 전이, 세션 저장, 두 박자 표정
```

## 2. 항목별 비교

| 항목 | AS-IS 1 초기 GPT 챗봇 | AS-IS 2 결정론 엔진 | TO-BE |
|---|---|---|---|
| **대화를 누가 정하나** | GPT가 전부(프롬프트 지시뿐) | 코드가 전부(상태, 질문 목표, 기법, 인용 대상) | GPT가 경계 안에서 정하고 코드가 검증 |
| **자연스러움** | 자연스럽지만 통제 불가 | 정해진 순서대로 질문, 맥락 무시(실사용 평가 2.2/5) | 맥락을 따라감(실사용 평가 4.75/5) |
| **근거** | 근거 검사 없음. 더미 데이터와 무관한 RAG 사례를 참고로 줌 | 코드가 고른 근거만 사용 | 코드가 준 id만 인용 가능(스키마 enum + 검증). 없는 기록·앱 기능을 말하면 거절 |
| **사용자 데이터** | 앱에 넣은 `dummy.json`(실제 사용자 아님) | 실제 백엔드(일기, 과거 상담 요약) | 실제 백엔드 + 합성 데모 계정 |
| **RAG·지식** | 다른 도메인(중독 상담) 사례 임베딩 | 승인 CBT 코퍼스(1~8주차) | 같은 승인 코퍼스. 현재 주차까지 누적, 미래 주차 금지 |
| **안전** | 별도 위기 판정 없음(프롬프트 의존) | SafetyGate가 먼저 판정, 위기면 고정 응답 | 같음. 위기면 GPT를 부르지 않음 |
| **금지 표현** | 프롬프트 지시뿐 | 코드 문장이라 원천 차단 | 검증기: 진단, 결과 보장, 상담 지시·조언, 시도 전 예시, 반말, 2인칭 |
| **기법(CBT)** | 프롬프트의 주차 컨셉 문구 | 상태별 selector가 승인 기법 선택 | 승인 기법 목록 안에서 GPT가 시점 선택. 기법 성과 인정은 코드 규칙 |
| **용어 질문** | GPT가 자유롭게 정의 | 대응 없음 | 코드가 용어 판정 → 승인 코퍼스 정의 하나만 전달. 목록 밖 용어는 정의하지 않음 |
| **과거 기억** | 없음(세션 저장 안 함) | 세션 요약 저장. 비슷한 걱정이면 기법 단계에서 지난 대안 생각 상기 | 저장 + "예전에도"라고 하면 코드가 기록을 골라 GPT가 직접 말하게 함(안 말하면 코드가 기록 그대로 보완). 일기에 적은 대안 생각도 참고 |
| **불안 점수** | 프롬프트 재량 | 세션 첫 턴마다 "0에서 10 사이로 표현하면?" 질문 | 묻지 않음. 불안 점수는 앱의 불안 평가에서만 기록하고, 챗봇은 그 기록을 읽기만 함 |
| **앱 사용법 질문** | 대응 없음 | 키워드 분기로 앱 안내 응답(상담 중에는 자주 놓침), 안내 지식 9개 | 같은 턴 안에서 상담·앱 안내·혼합으로 답함(앱 사실 id 근거 필수). 실제 앱 기준 기능 24개·사용법 10개, 없는 기능은 "없다"고 답함 |
| **불만·헷갈림·맥락 밖 입력** | GPT 재량 | 규칙 인식. 처음 보는 표현은 놓침(헷갈림 0/12) | GPT가 이해하고 방식을 바꿈. 한 번 다시 설명해도 안 통하면 질문을 내려놓음 |
| **종료** | 없음 | 마무리 핸드셰이크. "종료" 같은 표현은 놓침 | 사용자가 끝내자고 하면 바로 마무리(B·A 모두) |
| **상담사 표정** | 상담사 답을 GPT로 한 번 더 판정(매 턴 추가 호출), 그림 9종 | 사용자 말의 단어 규칙 + 상담 단계 기본값. 걱정에도 "생각하는 얼굴" | 두 박자: 보내면 듣는 얼굴 → 답이 확정되면 "사용자 정서 × 실제로 나간 응답 행동". 추가 호출 없음, 있는 그림 5종만 |
| **실패 시** | 오류 문구 | 코드 문장(항상 동작) | 그 턴만 A가 답함. 세션은 끊기지 않음 |
| **GPT 호출 (턴당)** | 2~3회(응답, 인지왜곡, 표정) | 0~1회(문장 다듬기) | 1회(+대체 시 A의 0~1회) |
| **관측** | 없음 | 기기 로그 일부 | 턴마다 `LLM_LED` 로그: 경로, 거절 사유, 실패 분류(429·5xx·시간 초과 등), 지연 분해 |
| **개인정보** | 백엔드 AI 프록시(`/ai/chat`)로 대화 원문 전송, 계정 구분 없음 | 원문 저장 안 함, GPT는 허용 계정만 | 같음. 사용자 원문이 OpenAI로 가는 B는 허용 목록 계정만, 로그는 가명·문장 없음 |
| **테스트** | 없음 | 단위·대화 재현·홀드아웃 회귀 | 같음 + B 계약·검증기·표정 단위 테스트, 데모 스모크(실제 백엔드) |

## 3. 왜 바꿨나

**AS-IS 1 → AS-IS 2.** 초기 챗봇은 대화는 자연스러웠지만 근거와 안전을 보장할 수 없었습니다.
- 사용자 데이터가 더미였습니다.
- RAG가 다른 도메인 사례였습니다.
- 위기 판정이 없었습니다.
- 금지 표현을 막을 장치가 없었습니다.

그래서 모든 결정을 코드로 옮기고 GPT는 문장만 다듬게 했습니다.

**AS-IS 2 → TO-BE.** 결정론 엔진은 안전했지만 실사용에서 "규칙 기반처럼 맥락을 못 따라온다"는 평가를 받았습니다.
- 앱 질문을 상담으로 처리했습니다.
- "그만하자"를 걱정으로 받았습니다.
- "대화가 안 된다"는 말에 또 질문했습니다.
- 처음 보는 표현은 규칙을 계속 늘려도 따라잡지 못했습니다.

그래서 판단은 LLM에 돌려주되, AS-IS 1의 문제였던 근거·안전·금지 표현은 코드가 계속 소유하도록 경계를 나눴습니다.

**근거 (같은 사용자, 실기기 블라인드 비교, 1~5점 평균, A = AS-IS 2 / B = TO-BE)**

| 항목 | A | B |
|---|---|---|
| 자연스러움 | 2.2 | 4.75 |
| 맥락 이해 | 2.8 | 4.25 |
| 상황 대처 | 2.0 | 4.5 |
| 진행감 | 2.0 | 4.5 |
| 계속 상담하고 싶음 | 1.6 | 4.25 |

평가자 1인, 평가 세션 9개라 한계가 있습니다. 이후 운영 개선으로 대체 비율은 23%에서 데모 스모크 기준 0%가 됐고,
상담 조언 노출 0, 종료 처리 실패 0을 확인했습니다.

## 4. TO-BE에서 일부러 남긴 것

- **A(AS-IS 2 엔진)는 지우지 않았습니다.** 주 상담 엔진으로 더 키우지 않고, B가 실패한 턴에 안전하고 확실하게 답하는
  대체 경로로만 씁니다. 허용 목록 밖 계정도 A로 동작합니다.
- **경계는 코드가 소유합니다.** 오류가 나도 결정론으로 되돌리거나 경계를 LLM에 넘기지 않고, 이 경계를 기준으로
  고칩니다. 대체 비율은 검증을 느슨하게 해서가 아니라 모델이 처음부터 맞게 쓰도록 해서 낮춥니다.

## 5. TO-BE의 남은 과제

| 과제 | 내용 |
|---|---|
| 임상 검수 | 상담 문장, 위기 응답·키워드, 1~3주차 기법 승인 |
| 운영 | 릴리스 빌드·HTTPS, 서버 측 kill switch, 서버 텔레메트리, 운영 서버 배포, 상담용 키·사용량 분리 |
| 품질 | 숨은 두 번째 질문·반복 질문으로 인한 대체 감소, A 대체 응답 다듬기, "하지 않은 말 인용"의 검증 규칙화 |
