# 상담 중 불안 기록과 알림 분석

상담 화면 진입 시 `GET /counseling/patterns`로 최근 28일의 기록을 집계한다. 로그인한 사용자에게 속한 완료 일기와 현재 활성 알림 설정만 사용하며, 분석 결과는 별도로 저장하지 않는다. 화면을 다시 열거나 상담 컨텍스트를 명시적으로 새로 고치면 최신 상태를 다시 조회한다.

- 일기 발생 시간은 `loc_time.time`을 사용한다. 없거나 잘못됐으면 일기 작성 시간으로 분리해 집계한다.
- 요일은 발생일이 아니라 일기 작성일 기준이다. 현재 데이터는 발생 날짜를 별도로 보장하지 않는다.
- 같은 시간대, 요일 또는 상황은 세 번 이상일 때 제시한다. 장소는 한 건 이상이어도 건수와 함께 표시하며, 세 건 미만은 반복이라고 표현하지 않는다. 반복 기준은 개발용이며 임상 기준이 아니다.
- 일기별 마지막 불안 점수가 한 건 이상이면 유효한 건수와 평균을 제시한다. 세 건 미만은 경향으로 단정하지 않는다. 중재 전후 효과나 환자 진단을 의미하지 않는다.
- 활성 알림은 일기에 기재된 시간과 1시간 이내이고 일기 작성 요일이 알림 요일에 포함될 때만 비교한다. 위치 알림은 장소명도 같아야 한다. 서울 이외 시간대는 비교하지 않는다. 현재 설정을 과거 일기와 비교하므로 과거에 해당 알림이 설정됐거나 실제 전달됐다는 뜻은 아니다.
- 주소로 보이는 장소, 좌표, 주소 필드는 결과에서 제외한다. 장소명은 패턴을 직접 질문했거나 현재 발화와 직접 관련될 때만 상담에 제공한다. 상황과 장소의 이름은 사용자가 입력한 값이므로 서버 로그에 남기지 않는다.
- 사용자가 패턴 분석을 직접 요청하면 시간·장소·점수·상황의 대표 집계를 우선 선정해 AI에 전달한다. AI가 근거를 빠뜨리거나 바꾸거나 호출에 실패하면 계산된 결과를 그대로 보여준다. 일반 상담에서는 발화와 관련된 집계만 LLM의 근거 목록에 제공한다. ID 및 문장 검사는 LLM 전체 답변의 정확성을 보장하지 않는다.
- 내부 계정의 AI 상담이 켜져 있으면 명시적인 분석 요청 외에도 최근 사용자 발화를 별도의 AI 호출로 분류한다. 자신의 상태나 상황을 살펴봐 달라는 뜻이면 같은 집계를 전달한다. 분류에는 마지막 발화만 보내고 일기와 집계 자료는 보내지 않는다. 분류가 실패하거나 4초를 넘기면 기존 규칙과 일반 상담 경로를 사용하므로 일부 표현은 인식하지 못할 수 있다. 이 호출은 응답 시간과 API 비용을 추가한다.
- LLM 사용이 불가능하거나 답변 검증에 실패하면 관련 기록을 한 번 안내하고 사용자에게 관련 여부를 묻는다. 위기 신호, 종료 요청, 기록 언급 중단 요청은 우선한다. 기록 언급 중단 설정은 현재 상담 세션에만 적용된다.
- 패턴 분석 조회에 실패하면 기존 상담을 계속한다. 사용자가 분석을 요청했을 때는 조회 실패를 안내한다.

## 확인과 배포

백엔드 테스트는 `PYTHONPATH=backend/app backend/.venv/bin/python -m pytest backend/app/tests -q -p no:cacheprovider`, 상담 테스트는 `flutter test --no-pub test/counseling`으로 실행한다. 기존 서버를 재시작해야 신규 API가 등록되고 Flutter 앱도 재시작해야 한다. 외부 서버에 적용하려면 백엔드와 앱의 별도 배포가 필요하다.
